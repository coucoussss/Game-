### [ball00] Ricocheted and ground-bounced shells keep full striking velocity and penetration, and can never ricochet again
- kind/impact/effort: bug/5/S
- files: /home/user/Game-/chars/game.js
- where: hitTank l.1776-1781 (xm = s.dist*RK; V = Ballistics.velAt(sb, xm); pen; ricP = s.ric < 1 ? ... : 0), ricochet branch l.1812-1824 (s.base *= 0.72, s.ric++), hitGround l.1543-1549 (x0.6, s.ric++), updateShells l.1466 (tankCand gets (s.z+zNext)/2) and l.1491 (true speed vr = s.v0*s.sp/s.sp0, already computed)
- problem: Striking velocity is computed from distance travelled only. After a ricochet off armour, the true speed is 0.72x. After a ground bounce, which happens with P = 0.75-0.07*fall whenever fall < 7° (most low misses), it is 0.6x. Either way the next tank hit uses the full velocity and the full penetration. Example: Panther APHE at 300 m (896 m/s, 172 mm) ricochets off a glacis. Its real speed is 645 m/s, giving 107 mm (0.72^1.43 = 0.625) before any tumbling penalty, yet the game still uses 172 mm. A ground-bounced round should have 0.6^1.43 = 48% of its penetration. Because ricP becomes 0 once s.ric >= 1, a bounced or deflected round can never ricochet again, even at 85° incidence. The impact height for tanks is the midpoint of the whole step, not the height at h.t. After a ricochet the slope reaches 0.4-1 m/m and dz per step is about 3-6 m, so turret/hull and height assignments are wrong.
- proposal: 1) In hitTank use the true speed: V = s.v0 * s.sp / s.sp0. This includes drag and every ricochet loss, and is the same value updateShells uses for gravity. 2) Set s.yaw = true on any ricochet or ground bounce. Then pen *= 0.5 (a yawed, deformed round loses 40-70%). Effective obliquity +10°. APHE: if the first plate was >= s.sens, 50% chance the fuze already functioned, so it explodes externally. 3) Replace the 0 with ricochetChance(sb, mm, angle) with both thresholds lowered by 10°, because yawed rounds ricochet more easily. 4) In tankCand, take the AABB t first and pass z = s.z + (zNext - s.z) * hh.t instead of the midpoint (same as the obstacle code at l.1456). Verify with ?debug: force a 75° ricochet into a second tank. The hitcam line 'Impact velocity' must show about 0.72x and the pen must drop to about 0.3-0.6x.

### [ball04] No shatter: APCR at an angle and uncapped AP at high velocity never fail

- APCR: p = clamp((ang-25)/30, 0, 0.9), +0.2 if T/(0.4·cal) > 2.5. On shatter, pen *= 0.55 and no core follow-through.

Show 'SHATTERED' as float text and in the hitcam (metal sim with marg < 0.83). Show 'shatter risk xx%' in the sight readout next to the ricochet %. ### [ball06] Mantlet is a random flat plate; shot traps impossible; ricochet direction not 3D
- kind/impact/effort: feature/4/M
- files: /home/user/Game-/chars/game.js, /home/user/Game-/chars/models.js
- where: game.js platePick l.1737-1740 (slope = Math.round(rnd(0, 30))), plateNormal l.1588-1593 (normal z always +sin for upper plates), ricochet branch l.1810-1840 (2D reflection on AABB normal h.nx/h.ny, s.owner = t); models.js mantlet types box/cyl(r 0.3)/bell
- problem: The mantlet slope is re-rolled on each hit regardless of where it lands. The normal always points upward, so every ricochet goes up, and s.owner = t forbids hitting the same tank again. Ricochet: build R = d - 2(d·n)n in 3D. Set vx/vy from R's horizontal part (rotated back to world) times |v|·0.72, and slope from R[2].
