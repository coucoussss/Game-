# Package B1: CrazyGames compliance, robustness, platform bugs

## Package-specific instructions
- CrazyGames rules: no native alert/confirm/prompt (custom modal), no in-game fullscreen button (the platform has one: remove ours), ads only through the SDK, mute and pause during every ad (input ignored too), respect SDK settings muteAudio (listen to settings changes), gameplayStart/Stop correctly paired, loadingStart as early as possible, happytime sparingly, no external links, wheel/arrow/space must not scroll the host page.
- Auto-pause on blur / visibilitychange / pointer-lock loss during battle (show the pause screen), resume audio state correctly.
- Move campaign unlocks, survival record and every persisted value into the Meta profile (cloud-saved through SDK.data) with a profile version and a migration from the old localStorage keys ('frontdacier.unlocked', 'frontdacier.survie'). 'Erase progress' must work on CrazyGames (clear SDK.data and localStorage) through a custom confirmation modal.
- Dev URL parameters (?level, ?type, ?mode, ?wave, ?auto, ?speed, ?2d, ?event...) must only work when ?debug is present; they must never persist unlocks or rewards to the profile. tools/smoke.js always passes ?debug so it keeps working: keep it working.
- Bundle the fonts locally: download Oswald and Inter woff2 (latin subset, weights used) into chars/fonts/ with their OFL license text, use @font-face, remove the Google Fonts links. Use the agent HTTPS proxy (see /root/.ccr/README.md if curl fails). If download is impossible, fall back to a system font stack and say so.
- music/menu.mp3 is missing: remove the 404 (audio package B5 will add synthesized music later; leave a clean hook playMusic/stopMusic). Do not ship the French music README in the zip (tools/build.py skips .md already: check).
- Robust main loop: catch exceptions per frame (log once, keep running), boot promise with catch and timeout so the loading screen never hangs.
- WebGL context loss/restore handling for world3d and gl3d (rebuild GPU resources on restore).
- Stop rendering the 3D battlefield while the menu is shown or paused (only the showcase renders in the menu).
- Content sensitivity: recolor/rename the 'Grand Parade' legendary skin so it does not evoke a Nazi flag palette (e.g. 'Victory Parade': olive, sand and brass), keep the id 'parade' so owners keep it.
- Store assets: generate CrazyGames cover images from real renders of the game (playwright screenshots of the showcase/battle + the STEEL FRONT logo composited): chars/store/cover-1920x1080.png, cover-800x1200.png (portrait), cover-800x800.png, plus a favicon (link it in index.html as an inline data URI or a small file shipped in the zip). Store images are not shipped in the zip.
- French leftovers in the UI: hunt them all (grep accented chars and French words in string literals across all js and html) and translate to English.
- Keep tools/build.py and tools/smoke.js working; update them if file layout changes (fonts/ folder must be in the zip).

### [comp00] Revive countdown keeps running during the rewarded ad: gameplay resumes behind the ad and the paid-for revive is lost
- kind/impact/effort: bug/5/S
- files: chars/game.js, chars/meta.js
- where: game.js openRevive() ~4045-4061 (setInterval countdown), closeRevive() ~4063-4068, $('revAd').onclick ~4083; meta.js requestAd() 46-62
- problem: openRevive starts an 8 s setInterval that calls closeRevive(false) at el >= 8. Clicking 'Repair (ad)' starts Meta.rewarded without stopping that interval. Real rewarded ads last 15-30 s, so the countdown expires mid-ad. closeRevive(false) then sets state='play' and calls Meta.sdk.gameplayStart() while the ad is playing, and the simulation resumes behind it. When the ad finishes, closeRevive(true) runs revivePlayer() without checking state. Reproduced with a mock SDK (12 s ad, clicked with 6 s left, Survival mode). SDK log during the ad: requestAd:rewarded, adStarted, gameplayStart. State was 'ending' during the ad. After adFinished, the result screen was up and player.dead was false. The player watched a full ad and got nothing, and gameplayStart fired during an ad, which breaks the SDK rules.
- proposal: Expose Meta.adActive() (adBusy getter). In revAd.onclick: clearInterval(reviveIt) and remember the remaining time. Then call Meta.rewarded(() => closeRevive(true), () => { toast(...); restartReviveCountdown(remaining); }). In closeRevive(ok), only call revivePlayer() if state === 'revive'. Make the interval callback a no-op while Meta.adActive(). To verify, reuse the mock SDK with __adDur=12000. Expect no gameplayStart between adStarted and adFinished, and expect state 'play' with player.dead false after the ad.
